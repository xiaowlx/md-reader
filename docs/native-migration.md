# 原生化改造：只留渲染用 WebView

> 决策时间：2026-09-28
> 用户决定：**只有必要的渲染用 WebView，其他都是 C#。**

## 一、目标架构

```
┌───────────────────────────── WPF (C#) ─────────────────────────────┐
│  原生标题栏（ui:TitleBar）  M↓ │ 文档标签 │ ⚙ │ — □ ×               │
├────────────────────────────────────────────────────────────────────┤
│  原生工具栏：打开 / 保存 / 另存为 / 编辑器模式 / 风格 / 主题 / 目录  │
├──────────┬─────────────────────────────────────────────────────────┤
│ 原生目录  │  编辑区（原生）        │  预览区（WebView2，只干渲染）   │
│ (TreeView)│  AvalonEdit（源码）     │  ┌───────────────────────────┐  │
│          │  RichTextBox（风格）    │  │ 收 markdown → 出 HTML     │  │
│          │                        │  │ ReactMarkdown + KaTeX     │  │
│          │                        │  │ + rehype-highlight        │  │
│          │                        │  └───────────────────────────┘  │
├──────────┴─────────────────────────────────────────────────────────┤
│  原生状态栏：字符 / 行 / 词 / 风格 / 脏标记                          │
└────────────────────────────────────────────────────────────────────┘
```

**边界一句话**：WebView2 退化成一个**纯函数** ——
输入 markdown 文本 + 风格 id，输出渲染好的页面。它不持有任何状态、不参与交互决策。

## 二、职责划分

| 能力 | 归属 | 说明 |
| --- | --- | --- |
| 文档模型（多文档、脏标记、路径） | **C#** | 唯一数据源 |
| 文件读写 / 关联 / 最近 / 会话 | **C#** | 已有 |
| 标题栏 / 标签 / 工具栏 / 状态栏 | **C#** | Wpf.Ui |
| 目录（大纲） | **C#** | 从 markdown 文本直接解析标题，不再依赖 DOM |
| 编辑区 | **C#** | AvalonEdit（源码）/ RichTextBox（风格） |
| 弹窗（关于 / 未保存 / 属性） | **C#** | Wpf.Ui MessageBox / 自建 FluentWindow |
| **Markdown → HTML 渲染** | **WebView** | 唯一保留在网页的能力 |
| 16 套风格 | **CSS 在 WebView + 色板同步给 C#** | 预览用 CSS，原生外壳用同步来的色板 |

## 三、两个方向的消息（比现在少）

```
C# → WebView   { type:'render', markdown, style }     渲染这篇
               { type:'theme',  mode, bg, fg, bd, ac } 同步色板给原生外壳
WebView → C#   { type:'rendered', html, headings }    渲染完成（含标题列表）
               { type:'log', ... }                    运行日志
```

**关键收益**：网页不再发 `docs` / `title` / `session` / `stat`，
因为**它不再持有文档状态** —— 现在这一堆同步问题（会话被清空、参数签名错位）从根上消失。

## 四、分期（每期都能独立跑、可回退）

### 阶段一：状态栏 + 工具栏搬原生
- 网页把统计信息随渲染结果一起回传（`rendered` 消息里带 chars/lines/words）
- C# 画原生状态栏与工具栏；桌面端隐藏网页里的对应部分
- **验证点**：原生控件与网页内容的对齐、色板同步是否够用

### 阶段二：目录搬原生
- C# 用 Markdig 解析 markdown 的标题（不依赖 DOM）
- 原生 `TreeView` + 滚动高亮（滚动位置由 WebView 回传）
- **验证点**：解析结果与网页渲染出的标题是否一致（含代码块里的 `#`）

### 阶段三：编辑区搬原生
- 源码模式 → **AvalonEdit**（自带行号、查找替换、语法高亮）
- 风格模式 → **RichTextBox**（先做只读，编辑后续）
- **验证点**：编辑体验是否退化；撤销栈、快捷键、中文输入法

### 阶段四：弹窗与其余交互搬原生
- 文档属性、拖放提示、toast → 原生

### 阶段五：拆掉网页里的外壳
- `app.jsx` 瘦身到只剩「收 markdown → 渲染 → 回传」
- 网页标签栏、顶栏、状态栏、目录、日志面板全部删除

## 五、必须用到的成熟件

| 用途 | 选型 | 备注 |
| --- | --- | --- |
| Markdown 解析（C# 侧） | **Markdig** | .NET 事实标准 |
| 源码编辑器 | **AvalonEdit** | 自带查找替换、行号、折叠 |
| 高亮（预览） | rehype-highlight | 留在 WebView |
| 公式（预览） | KaTeX | 留在 WebView |
| 外壳控件 | **Wpf.Ui** | 已在用 |

## 六、已知风险

1. **风格下拉**：16 套风格的色板要能"导出"成 C# 可用的颜色 ——
   现在的 `theme` 消息只发 5 个色，要扩到一套完整的色板（约 12-15 个 token）
2. **编辑区换原生**是本方案里体验退化风险最大的一步 ——
   AvalonEdit 没有 Markdown 语法高亮（要自己写 `IHighlightingDefinition`）
3. **风格模式的富文本编辑**：contenteditable → RichTextBox 的 markdown 互转要自己写
4. 每期都要保证**浏览器版仍可用**（网页仍是完整应用，只是桌面端不用它的外壳）

## 七、不做的事

- 不重写 Markdown 渲染（保留 remark/rehype + KaTeX，这是保留 WebView 的全部理由）
- 不移植 16 套 CSS 主题到 WPF（原生外壳只需同步色板）
- 不追求一次到位
